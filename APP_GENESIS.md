# 🛠 Task Manager: App Genesis & Current State

This document chronicles the development and core logic of the **Task Manager & Financial Reporting System** as of April 2, 2026.

## 🏗 Core Architecture
- **Frontend**: React (Vite) + Tailwind CSS (Vibrant/Modern)
- **Backend**: Node.js (Express) + `node:sqlite` (Experimental Native SQLite)
- **Database**: Single file `database.db` with localized table management.

## 🗝 Core Features & Logic
### 1. Account-Based Sales Logging
- Every user acts as an individual "Account" with a balance.
- **Records Page**: Searchable `Particulars` dropdown with unit cost prices.
- **Auto-Calculation**: Cost price (`qty * unit_cost`) and Variance (`price - cost`) are calculated on entry.

### 2. Multi-Settlement Logic (Advanced)
- Users can settle funds multiple times a day.
- **Unsettled Records**: New sales are marked as pending.
- **Settlement Chain**: Each settlement starts with the `Kept Amount` of the previous one as its `Opening Balance`.
- **Linked Records**: Records are permanently linked to their settlement ID for auditing.

### 3. Financial Ledger (Admin/Superadmin)
- A central audit trail showing:
  - **Who sent what to whom**.
  - **Timestamped settlements** with expandable cost/profit breakdowns.
  - **Filtering** by date and specific staff.

### 4. Admin Control
- **Particulars Management**: CRUD for products/services and their base costs.
- **Staff Control**: Role-based access (Superadmin for user management, Admin for oversight).
- **Hidden Dev Panel**: A secure "Wipe" panel for test data (System Admin/dev identity only).
