TASK MANAGER SYSTEM — BUSINESS LOGIC & FUNCTIONAL SPECIFICATION

==================================================
🧠 SYSTEM PURPOSE
=================

This system is designed to manage internal operations across multiple branches of an organization.

It provides structured control over:

* Users (with hierarchy and authority levels)
* Tasks (assignment, tracking, completion)
* Branch-based access
* Future reporting capabilities

The system must reflect real-world organizational hierarchy and workflow.

==================================================
🏢 BRANCH STRUCTURE
===================

The organization operates across multiple branches.

Each branch represents a separate operational unit.

Examples of branches include:

* RS ONLINE
* CSP
* BLOCK
* CHUTIA
* PAYWORLD
* METOWE
* HOONER KENDRA
* RS WATER
* RS COMPUTER
* RS TRAVELS

Every user belongs to exactly one branch.

All actions performed by a user are scoped to their branch unless they have global authority.

==================================================
👤 USER LEVELS & AUTHORITY
==========================

There are three primary levels of authority:

---

1. SUPERADMIN

---

Aliases:

* CEO
* DEV

Capabilities:

* Full system access
* Can create, edit, and delete any user
* Can assign tasks to any user in any branch
* Can mark any task as completed
* Can view all data across all branches

This is the highest authority level.

---

2. ADMIN

---

Aliases:

* COO
* Accountant
* HR

Capabilities:

* Can assign tasks within their branch
* Can mark tasks as completed
* Can view users and tasks within their branch
* Cannot manage Superadmin accounts
* Cannot access other branches

Admins operate at a branch level.

---

3. OPERATOR

---

Alias:

* Coordinator

Capabilities:

* Can view tasks assigned to them
* Can update task status to "Check" (in_review)
* Cannot assign tasks
* Cannot complete tasks
* Cannot edit or delete tasks

Operators are execution-level users.

==================================================
🔐 USER MANAGEMENT LOGIC
========================

User management is controlled strictly by authority level.

---

## Superadmin:

* Can create new users
* Can assign roles and aliases
* Can assign users to branches
* Can reset passwords
* Can delete users

---

## Admin:

* Cannot create or delete users
* May view users within their branch

---

## Operator:

* No access to user management

User creation must include:

* Name
* Email
* Password
* Role
* Alias
* Branch

==================================================
📋 TASK MANAGEMENT SYSTEM
=========================

Tasks are the core functional unit of the system.

Each task contains:

* Title
* Description
* Assigned By (user)
* Assigned To (user)
* Status

---

## TASK STATUS FLOW

Tasks follow a strict lifecycle:

1. pending

   * Task is created and assigned

2. in_review (Check)

   * Marked by Operator when work is done

3. completed

   * Marked by Admin or Superadmin after verification

---

## ROLE-BASED TASK CONTROL

Superadmin:

* Can create tasks
* Can assign to any user
* Can mark any task as completed

Admin:

* Can create tasks
* Can assign tasks within branch
* Can mark tasks as completed

Operator:

* Can view assigned tasks
* Can mark task as "in_review"
* Cannot mark completed
* Cannot edit task details

---

## IMPORTANT RULES

* Only Admin or Superadmin can finalize tasks
* Operators cannot bypass review stage
* Task creator cannot be overridden by lower authority

🎯 SYSTEM BEHAVIOR SUMMARY
==========================

* Every user operates within a defined authority level
* Every action is restricted based on role
* Every user belongs to a branch
* Tasks flow through a controlled lifecycle

==================================================
🧠 DESIGN PRINCIPLE
===================

The system must reflect real-world hierarchy:

Superadmin → controls system
Admin → manages operations
Operator → executes tasks

There should be no ambiguity in permissions.

If a user should not have access in real life, they should not have access in the system.

* Return user object
